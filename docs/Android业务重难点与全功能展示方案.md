“展示所有功能”的验收口径为：全部已实现功能具有移动端入口、完整详情、适用的操作和结果反馈；同一功能对有权限的用户可见、可操作。权限未授权的能力不能为了展示完整而开放。成本测算、AI 报告生成（定制）两个菜单当前仍为占位，保留“升级中”状态。

**难点一：融资品种多，动态表单和关联对象复杂**

债务表单不仅有基础信息，还包括债权单位、共同债务单位、担保措施、还款主体、收款账号、合同附件、本金计划、利息计划和附属费用。债券、票据、保证金等品种具有不同字段；切换品种可能使已有输入失去适用性。

采用 Compose 分组表单 + 强类型 Kotlin Draft + ViewModel 状态归约。复杂业务表单由专用组件承担，金额、日期、机构选择等基础控件共用。用字段规则描述适用性、必填和可编辑条件；已有后端 schemas/业务规则为依据，不能假定已经存在可直接驱动全部表单的 JSON Schema 接口。

手机分成“基本信息—资金方/担保—本息及费用—附件与确认”等逻辑分组；长期草稿放 Room，SavedStateHandle 只保留轻量导航状态。类型切换时展示受影响字段，并明确清理或保留策略。每个重复明细使用稳定行 ID，避免插入、删除或排序后金额串行。

机构选择使用远程搜索、树形路径与分页候选；提交记录 ID，不只提交显示名称。基础资料新增完成后将新 ID 带回原草稿。整个表单与 AI 对话修改同一份 Draft，避免两套字段来源相互覆盖。

验收必须覆盖所有品种、保证/抵押/质押组合、主附债务关系、费用明细、编辑旧数据及类型切换，不以某一种贷款能保存代表表单完成。

**难点二：金额、利率、还款计划必须与 Web 一致**

重点包括元/万元/亿元、百分比与基点、计息基准、节假日顺延、合同到期日与实际付款日、LPR 重定价、分段本金、保证金利息抵扣、还款日是否计息、历史锁定、利率反算和 IRR。

Android 用 BigDecimal 保存和展示金额；精度和舍入逐字段遵守后端合同，不能对所有数值统一保留两位。金额传输按接口真实的 JSON 类型适配，不能先转 Double 再恢复 Decimal。图表坐标可以转换为近似数值，标签、合计和导出使用原始十进制结果。

正式计算集中到后端现有纯业务服务，复用利息预览、浮动利率计算、票据到期预览、余额查询等接口。Web 特有的计划生成、转换、反算逐项核对；缺失部分先补后端服务/API，让 Web 与 Android 共用。App 的即时校验只负责输入完整性，不另建一套权威计息引擎。

采用现有 pytest 财务测试 + 同输入输出对照样例。验收包括月末、闰年、跨年、LPR 切换、节假日、部分还本、抵扣、舍入和历史重算；误差门槛按现有业务规则逐项确定。用户看到的每期金额、合计、保存后的结果和导出必须一致。

**难点三：手机窄屏承载完整台账和复杂统计**

每类台账提供“卡片列表、完整表格、完整详情”三个视角。卡片优先展示名称、金额、状态和日期；完整表格展示用户授权可见的全部列；详情包含全部适用字段、关联记录、附件、历史和动作。摘要不承担完整字段展示。

Native 台账使用 LazyColumn 按需布局，服务端分页和排序；使用共享横向偏移同步表头与数据列，冻结标识列。特别宽的表需做可见列裁剪并真机验证，不能认为 LazyColumn 自动解决二维虚拟化。排序、筛选、全选和导出基于服务端完整结果，不只处理当前页。

分页台账提供页码和总数；聊天、日志、文件历史等适合连续浏览的页面使用 Paging 3。视图的业务字段、筛选和排序可以复用后端 table_views；手机列宽单独保存。大批量选择用已有选择 ID 接口或新增服务端选择集，避免前端拉全量再筛选。

冻结列、列显隐/顺序/宽度、保存视图、筛选条件回显、横屏和明细跳转都属于实际功能。目标规模根据真实数据确认，使用 Macrobenchmark 检查滚动、切页与内存峰值。

**难点四：聊天和业务任务能够连续办理，但服务器不保存对话**

手机保存 Conversation、Messages、ContextSummary、BusinessDraft、PendingAction 和父子任务关系。服务器每轮读取必要上下文，在请求内构造 Agent 工作状态，返回结构化增量和回复。最近对话、确认过的业务事实、草稿版本和当前待办一同参与上下文；不能仅截取最后若干条文字。

保留现有 render_card、open_form、navigate、run_query 的交互语义。返回内容用 Pydantic 验证和版本化协议约束；Android 用类型化模型路由到原生卡片、表单与业务页面。既有 Agent 中的正式写入路径逐项梳理；所有正式写操作仍受服务器授权、业务校验和适用的用户确认约束。

每个会话串行提交轮次，携带本地 draft_version；迟到响应不能覆盖更新草稿。编辑历史消息后，旧卡片及依赖其生成的草稿需失效或重建；默认先支持可靠的连续对话，再实现有明确失效语义的重生成。

移动端直接调用既有 Assistant 会话与消息接口，服务端继续保存消息、上下文、工具轨迹及按实现生成的摘要/请求响应。App 不复制一套本地聊天历史；重新登录后从服务端恢复会话。服务端模型日志、远程追踪、保留期限和删除能力需要形成可审计配置，并在产品隐私说明中披露。正式业务写入仍需独立提交回执和幂等控制；响应丢失时先查询业务结果，不能仅靠重新发送对话判断是否成功。

长对话摘要同样敏感，只保存在手机。服务器可以临时生成摘要后返回。数据库、反向代理、模型服务、异常监控和客户端日志均按该规则验证。不能因为已有依赖含 LangSmith/Sentry 就断言已启用外传，也不能不检查实际配置。

聊天和草稿可用 AES-GCM 加密成不透明内容后写 Room；按账号隔离，密钥由 Keystore 管理，不把聊天正文建成明文全文索引。Keystore 的密钥保护机制参考 [官方说明](https://developer.android.com/privacy-and-security/keystore)。聊天与敏感临时文件排除系统云备份及未经定义的设备迁移，规则参考 [Android Auto Backup](https://developer.android.com/identity/data/autobackup)。

本地历史的必然结果是：同一账号换手机不会自动出现历史聊天；卸载或丢失密钥后不能从服务器恢复。业务记录仍能按权限从后端查看。加密的用户主动迁移可以后续单独定义，不默认为已经具备。

**难点五：OCR 需要可核对、可修改、可继续录入**

CameraX 负责拍照；文件选择器接收 PDF、图片、Word、Excel 等后端支持的类型。App 做体积、格式和页数提示，后端完成最终校验。上传流式读取到私有临时文件或请求流，避免把全部文件解码到内存。

OCR 复核采用“原文 + 字段结果”模式：竖屏可切换，横屏可并排。页图由后端既有接口获取；Compose Canvas 将字段证据框从原始页面坐标转换到当前缩放、旋转和位移后的坐标，支持点击字段定位原文及返回字段编辑。只有接口实际提供证据的位置才高亮，没有证据不能伪造定位。

字段显示识别值、人工修改值及来源；金额、主体、日期等问题提供逐项复核。保存识别文档、修改分析、替换原文件、生成业务预填是不同动作，界面分别呈现。预填后进入正式业务表单，提交时重新校验，避免识别结果直接成为未经核验的正式记录。

合同模块树、资料目录、归档、文件整理、基础材料绑定、三年一期材料、候选材料和打包都要有入口。模型调试与性能指标继续受对应权限控制。

**难点六：自动填表包含表头、规则、映射和人工确认**

自动填表流程明确展示为：上传模板 → 识别结构 → 映射复核 → 查询/计算 → 结果预览 → 确认生成 → 下载。任务实际有哪些状态及允许操作，以现有接口为准。

映射复核使用原生字段列表，展示 Excel 列、业务字段、转换规则和冲突；复杂合并表头、工作表和原格式预览使用自有 HTML/CSS 渲染组件。WebViewAssetLoader 加载 App 内打包页面，数据通过受限桥接传递；字段内容做文本转义，不执行文件或模型提供的脚本，禁止外站跳转及外部资源加载。官方嵌入本地内容方式见 [WebViewAssetLoader 文档](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)。

Android 不实现完整 Excel 编辑器，也不自行运行任意单元格公式。现有修改映射、确认预览、重试、重跑、导出字段/规则等业务操作全部通过原生面板完成；预览与导出由服务器同一业务结果驱动。需要对合并表头、宽表、多个工作表及超大模板逐项确认接口覆盖和预览限制。

**难点七：上传、识别、填表、导出、备份都是长任务**

统一任务中心显示类型、阶段、状态、进度、关联业务、创建时间和可用操作。前台使用生命周期绑定的协程轮询，切到后台后由适用的后台调度恢复；服务器继续执行已创建任务。服务器任务 ID 存 Room，App 重启后查状态，不重建任务。

现有任务能力并不一致：有些持久化，有些重启后标记中断；并非所有任务都可取消或续跑。任务适配层声明 supportsCancel、supportsRetry、supportsResume，只有服务端支持的操作才开放。无可靠进度时展示阶段和等待状态，不显示虚构百分比。

WorkManager 用于允许延迟的传输和恢复，不承担聊天流式输出或秒级进度。长传输根据目标 Android 版本采用适用的用户发起数据传输/前台执行机制；Android 16 的长 Worker 配额限制见 [官方说明](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running)。

备份恢复已有分片上传协议，可以复用；普通 OCR/附件上传不能因此宣称已经支持断点续传。下载也只有服务端验证支持 Range/ETag 后才能可靠续传；缺失时重新下载，并避免自动重复产生业务副作用。

**难点八：部门协同、重复提交和同时编辑**

用户可能在 Web 和 App 同时修改项目；提交成功后网络中断也可能导致用户重试。仅禁用按钮不能防止重复创建和覆盖。

正式写接口逐项补齐或验证：client_request_id、预期业务版本、请求参数指纹、后端唯一约束、SQLAlchemy 事务和最小回执。相同请求键与相同参数返回原结果，相同键不同参数拒绝。已有 assistant_action_id 路径需要与服务端会话 ID、版本和回执衔接，不能假设所有业务接口已实现幂等。

冲突时返回明确的 409 或既定冲突合同，App 展示当前服务器版本与本地修改，允许用户重新编辑后提交；金额、还款状态、作废与恢复不自动合并。通过现有 /sync/changes 使相关缓存失效，再拉取最新对象；处理 has_more、invalidate_all 和 reset_required。

主记录与附件分步保存时，展示“主记录已保存、附件待重试”，只重试附件，不重建主记录。服务器恢复备份期间全局展示维护状态，暂停相关写操作，恢复后重新刷新业务数据和权限。

**难点九：完整权限和系统管理也必须在手机可用**

从 /auth/me 获取当前权限，结合权限目录建立菜单、页面、按钮和数据范围能力。所有导航入口，包括 AI 卡片、任务结果、关联链接和搜索，都经过同一权限判断。服务端在每次请求执行最终授权，不能信任客户端传回的用户 ID 或权限列表。

登录实现现有验证码触发合同、密码修改、退出与真实交互续期；401 返回登录，403 展示权限不足，业务草稿按账号保持隔离。后台请求不能无限续期登录。权限改变、账号停用、切换服务器或用户后清理失效缓存。

管理页全部建立移动入口，包括角色权限依赖、用户管理员交接、LPR/节假日导入发布、规则发布、备份恢复及维护释放。危险操作用原生确认页呈现实际影响和对象；是否允许由现有后端权限决定。开发测试操作遵守已有环境约束，不能在正式环境额外开放。

**难点十：统计、报表和打印需要保留数字依据**

首页展示关键指标，点击钻取到相同条件的明细。综合查询显示主体范围、时间基准、单位、筛选条件、数据更新时间和后端返回的说明/警告。分页结果的全量合计从服务器取得；集团合并口径也由服务器计算，Android 不再自行汇总推断。

指标卡使用 Compose，复杂图表使用本地 ECharts。图表只接收授权后的聚合数据，事件回传白名单化，导航目标由原生层校验。每张图都可以打开对应数表与明细，满足精确核对。

Excel/Word 保留现有导出；App 内正式打印采用 PDF + PrintManager/PrintDocumentAdapter。现有导出不能直接等同于已经具有 App PDF 打印接口，需要新增或核实 PDF 预览与下载能力。Android 打印要求参考 [官方打印文档](https://developer.android.com/training/printing/custom-docs)。

PDF 生成优先复用受控报表模板；必须按既有 Office 模板还原时，可增加自有 LibreOffice 转换 Worker，官方支持命令行 PDF 转换，见 [LibreOffice 文档](https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html)。中文字体、分页、公式缓存与金额不截断需要样本验收，不能承诺任意 Excel 无损转换。文件打开/分享用 FileProvider 和临时 URI 授权；打印动作与现有单据打印记录接口按业务含义关联，系统打印取消不能被误记为已完成付款。

**AI 的全功能入口与业务执行范围**

所有业务都应有原生可点击入口；AI 不成为访问业务的唯一方式。助手可以打开用户有权访问的页面，并继续支持已经注册的业务工作流。

当前工作流目录覆盖：项目创建/查询/删除，债务创建，计划/实际资金速记创建，债务单位及债权机构创建，银行账号/发票/不动产/实控公司/工程项目的已注册增改删，对外担保增改删，还本付息单创建/查询/删除，以及合同、查询和 OCR 相关辅助链路。

对其余功能，先提供准确导航和原生操作。若要进一步达到“任意业务操作都可以用自然语言完成”，需要增加工具与确认协议并逐项验收，不能因页面全覆盖就宣称 Agent 执行能力已经全覆盖。系统恢复、权限调整、历史重算等动作保留明确的原生确认过程。

**需要新增或调整的后端能力**

| 调整 | 原因 | 交付边界 |
| --- | --- | --- |
| 复用 Assistant 持久化入口 | 现有入口保存消息、摘要、请求响应 | 保持会话版本合同、权限隔离和错误语义；补齐保留策略、删除能力与隐私披露 |
| 财务辅助计算接口覆盖 | 部分行为存在于 Web TypeScript | 先做前后端对照，再补齐计划生成/转换/反算等缺口 |
| 写接口幂等与冲突合同 | 手机重试、双端编辑 | 分业务核对并补齐，不能直接全局重试 POST |
| 任务能力适配 | 任务存储和取消/重试能力不一致 | App 统一展示协议，必要的服务器适配；不为统一 UI 虚构续跑 |
| PDF 预览/打印 | Office 导出不是 Android 原生打印格式 | 已有格式继续可下载，受控模板/转换服务补 PDF |
| 结构化预览与证据字段 | 复杂 Excel、原文坐标需要稳定合同 | 优先复用现有接口，只补实际缺口 |
| 功能/字段合同版本 | 后端演进可能导致表单、卡片和权限漂移 | CI 比较 OpenAPI/权限目录/字段映射，保持最低兼容版本 |

不因 Android 接入就更换数据库、改用微服务、引入全量离线同步，或默认新增 Redis/Celery。先复用现有后台 Worker，只有出现实际并发和恢复能力缺口时再评估基础设施。

**交付顺序与完成条件**

第一阶段建立完整功能目录、角色映射、公共列表/表格/表单/文件/任务组件，并验证最高风险链路：复杂债务录入及金额对照、服务端持久化多轮对话、OCR 原文定位、自动填表预览、App 内打印。原型验证覆盖的是架构风险，不代表其他功能可以从范围中删除。

第二阶段完成项目、融资明细、速记、现金流、协同、审批、担保授信的全业务链路。第三阶段完成所有 OCR/填表/材料/查询/报表与系统管理。阶段可以按团队规模调整，最终 F01—F40 均需明确验收结果。

功能覆盖矩阵每行至少包含：功能编号、页面路由、角色/数据范围、读取接口、写入接口、字段、状态/异常、导入导出、相关工作流、验收场景及结果。一个后端接口可能服务多个页面；后台健康检查等支持接口不必对应独立菜单。

| 验收维度 | 必须观察到的结果 |
| --- | --- |
| 全功能可发现 | 各角色授权范围内，每项已实现业务均可从全部功能或对象详情到达 |
| 完整字段与操作 | 摘要外可展开完整详情；适用新增、修改、删除、状态、历史、附件、导入导出等均有入口 |
| 财务一致性 | Web、App、保存结果、预览与导出按同一规则一致，边界计算逐项通过 |
| 全生命周期 | 创建—编辑—关联—办理—查询—历史—导出按实际业务状态完整走通 |
| 权限一致性 | 页面入口、AI 工具、对象读取和写入、附件、下载均不越权；角色变化后及时刷新 |
| 对话隐私 | 入口明确告知服务端持久化；会话按账号和 `assistant.view` 权限隔离；日志、模型服务边界、保留与删除策略可审计，正式业务审计仍可用 |
| 多轮正确性 | 补充/纠正、候选选择、子任务返回、任务取消、重启恢复、迟到响应不覆盖草稿 |
| 异常可靠性 | 断网、超时、登录失效、重复点击、并发编辑、进程退出、服务重启均不会造成重复正式写入 |
| 文件与任务 | 大文件内存可控，文件与任务均可查到结果；只承诺接口具备的取消/重试/续传 |
| 展示性能 | 真实台账规模、宽表、长聊天、多页合同和复杂模板在目标手机上达到约定指标 |
| 打印与导出 | 中文、金额、页码、表头与分页可核对；下载结果与查询条件一致 |

当前尚未锁定最低 Android 版本、典型设备、真实数据规模和性能指标。这些影响兼容性与验收阈值，不影响上述功能范围与在线业务架构。
