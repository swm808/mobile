# develop 后端驱动的移动端重建设计

- 设计版本：v1.2
- 更新日期：2026-09-23
- 后端基线：CityBond `develop` 提交 `390218ac3a1c13dbd0a3cf42b19603a3d130cf64`
- 实施状态：App 启动登录门禁、验证码、内存 Cookie 会话和 `/auth/me` 已接入；助手基础会话与全局悬浮入口已接入。权限驱动业务目录、维护模式、同步基座和正式业务读写仍待后续批次。

## 1. 重建目标

移动端不再依据演示数据或 Web 页面外观独立定义项目、债务、日历和 AI 文档业务。后续页面必须从同一固定后端提交的运行时 OpenAPI、Pydantic Schema、权限目录、业务状态机和服务端测试推导，Web 端只用于补充交互参考。

本次保留：

- `MainActivity`、Compose 主题和五个一级入口。
- 调试版 `/health` 连接检查。
- 基础网络依赖与既有网络单测。
- B02 核心模型和 Debug Mock，暂只作为历史设计样例；接入业务时不得直接当作后端 DTO。

本次移除：

- 项目台账、债务台账、日历统计和 AI 文档分析的运行期演示页面。
- 上述模块的展示模型、内存演示数据、深层路由和设备测试。
- 首页和业务页对这些演示能力“已就绪”的表述。

## 2. 合同来源与优先级

同一含义发生冲突时按以下顺序处理：

1. 固定提交启动后的 OpenAPI 请求/响应合同。
2. 后端 Schema、服务状态机、事务规则和自动化测试。
3. `permission_catalog.py` 的权限编码、依赖、数据范围和导航归属。
4. Web 前端的字段组织和交互方式，仅作为展示参考。
5. 既有移动端模型、Mock 和历史截图，不作为正式合同。

每个业务批次开始前记录后端提交号、涉及接口、权限码、DTO、状态流转和错误码。基线变化时先做合同差异检查，再修改页面。

当前 `a7da695f` 已生成两份互补附录：

- [运行时接口合同清单](develop后端接口清单.md)：418 个 OpenAPI 路径、509 个 HTTP 操作、850 个 Schema，含权限、请求及成功响应摘要。
- [静态路由查漏清单](develop后端静态路由清单.md)：生产应用源码 45 个文件中的 510 条装饰器声明；多出的 `app.modules.ocr.api.sheet_fill.patch_sheet_field` 未进入 OpenAPI，不能作为可调用接口。

生成过程只构造应用并读取 OpenAPI，没有进入 lifespan 或连接数据库。R01 实现 DTO 前仍应保存机器可比较的 OpenAPI 快照；目标环境联调时再次核对部署配置、数据库迁移和对象数据范围。

## 3. 应用分层

当前保持单个 `app` 模块，以包边界隔离职责；达到稳定规模后再拆 Gradle 模块。

| 层 | 建议包 | 职责 |
| --- | --- | --- |
| 应用壳 | `app` / `ui.shell` | 启动、一级导航、维护模式、全局会话失效和通用错误入口 |
| 合同层 | `network.contract` | 按 OpenAPI 定义请求/响应 DTO；禁止业务 Compose 页面直接解析任意 JSON |
| 会话层 | `auth` | 验证码、CookieJar、登录、`/auth/me`、活动续期、退出、权限版本 |
| 公共数据 | `core.data` | Retrofit 服务、Repository、错误映射、分页、同步令牌和缓存失效 |
| 业务用例 | `feature.<group>.domain` | 组合接口调用、服务端状态映射、版本冲突和提交确认 |
| 页面状态 | `feature.<group>.presentation` | ViewModel、StateFlow、加载/空/错误/内容状态、草稿和一次性事件 |
| 本地存储 | `local` | 普通偏好、账号隔离缓存与未提交业务草稿；AI 对话历史使用服务端 Conversation 持久化 |

页面不得直接写共享可变 Mock 列表。正式金额使用 `BigDecimal`，日期和时间分别使用 `LocalDate`、`Instant`，服务端枚举保留未知值降级显示并记录合同不兼容事件。

## 4. 导航与权限驱动

底部一级入口保持：首页、业务、助手、任务、我的。业务目录不硬编码角色名称，而是由 `/auth/me` 返回的 `permissions` 与 `permission_version` 决定。

| 目录分组 | 后端权限组 | 移动端入口 |
| --- | --- | --- |
| 项目与融资 | `overview`、`project`、`debt`、`pending_debt`、`memo`、`finance`、`engineering`、`asset` | 首页总览、项目台账、融资明细、资金速记和跨部门协同 |
| 技能与业务 | `ocr`、`sheet_fill`、`debt_init`、`query`、`documents`、`materials` | AI 录入、自动填表、综合查询、业务审批和材料打包 |
| 管理员功能 | `master_data`、`ocr_settings`、`ai_settings`、`backup`、`extraction`、`sheet_rules`、`parameters`、`users`、`permissions`、`holidays`、`lpr`、`audit`、`development`、`guarantee`、`credit` | 我的 → 管理功能，按权限逐项出现 |
| 独立入口 | `assistant` | 助手页；执行具体工作流时还必须拥有目标业务权限 |
| 占位入口 | `cost_estimation`、`ai_report_generation` | 仅在获得对应 `view` 权限时显示“升级中”，不得伪装成可用功能 |

权限目录 v3 的移动菜单映射已固化为 16 个菜单模块、33 个权限功能组：项目与融资 5 个菜单、技能 7 个菜单、管理员功能 3 个菜单、其他设置 1 个菜单。组合菜单以任一子功能的 `<group>.view` 决定可见，但进入子功能和执行动作时必须再次检查该组的具体权限。详细键值见[移动端需求文档的业务模块目录](移动端需求文档.md#移动端业务模块目录权限目录-v3)。

B08 页面是合同覆盖清单，不是正式业务导航：所有卡片明确显示“待正式接口接入”“后端升级中”或“等待隐私门禁”，没有业务点击动作。R01/R02 完成后，正式目录必须使用 `/auth/me.permissions` 过滤；不得把 B08 的完整开发清单直接当作当前账号可用菜单。

规则：

- 没有 `<group>.view` 时不展示该功能；直接深链访问仍由后端再次拒绝。
- `view_all`、`edit_all` 只影响数据范围，不替代 `view`、`edit`。
- 未知或缺失角色按零权限处理，不回退为普通用户。
- 401 清除会话并回到登录；403 保留当前草稿并提示权限不足；权限版本变化时清空旧菜单和动作缓存。
- 危险操作必须显示对象、影响范围和二次确认，不因前端隐藏按钮而放松后端校验。

## 5. 网络与状态合同

首批网络基座必须统一处理：

- Cookie 登录、验证码、超时、同源环境配置和 Release HTTPS 限制。
- 后端 `detail` 字符串或结构化错误、业务 `code`、401、403、409、422 和 5xx。
- GET 可按策略重试；POST、PUT、PATCH、DELETE 默认不自动重试。
- 版本化更新携带服务端 `version_no`；409 后刷新并让用户决定是否重新编辑。
- `/sync/changes` 处理 `token`、`has_more`、`reset_required`、`invalidate_all` 和实体 ID，不把它当成双向离线同步。
- 上传、OCR、填表、导出和恢复任务保存服务器任务 ID，按各自真实接口提供轮询、取消或重试。
- 维护模式停止业务写入；后台轮询不得调用用户活动续期接口。

所有 DTO 与数据库实体分离。列表 DTO、详情 DTO、编辑 Draft 和提交 Payload 分开定义，禁止用展示默认值覆盖服务端缺失值。

## 6. 最新基线的关键业务规则

| 范围 | 必须按后端实现的规则 |
| --- | --- |
| 项目/速记 | 展示实际到账额与已关联正式融资合计；删除正式债务时，关联实际速记及符合条件的来源计划在同一事务软删除 |
| 资金速记 | 草稿支持 `actual_received_amount`、扣款和保证金明细；列表筛选和汇总由服务端口径返回 |
| 不动产抵押 | 正数评估价值优先，否则回退账面价值；存量抵押全额占用，同项目拟抵押和正式抵押取较大值；编辑债务使用 `exclude_debt_id`，剩余担保余额只读 |
| 付息计划 | 周期付息生成明细作为日期快照持久化，但不能启用自定义金额计息；最后一期必须为到期日 |
| 附属费用 | 保存债务与收款账号收录结果分别反馈，识别 `created`、`reused`、`updated`、`incomplete` |
| 还本付息单 | 只有有效、待打印、未打印且关联现金流未支付的记录可编辑；提交完整快照、`version_no` 和必要的影响确认；提前还款由服务端重算未来计划 |
| 成本审批 | 支持全部、已打印、未打印、已作废筛选；打印完成后显式登记，保存次数、时间、人员和来源，取消或失败不登记 |
| Assistant | 每个工作流按目标业务权限授权；债务/债权单位支持别名、启停和候选复核；债务速记聊天草稿与手工表单共用明细合同 |

## 7. AI 对话与服务端持久化

用户已确认直接复用现有 Assistant 接口。移动端通过 Cookie 会话访问 `/assistant/conversations`，对话正文、上下文、模型回复、Turn 和 Agent 消息按 CityBond 现有数据库与日志策略保存。

1. App 在全屏助手与悬浮快捷面板中明确提示对话会保存到服务器。
2. 会话读取、消息发送和删除均依赖 `assistant.view`，业务工具继续检查目标业务权限。
3. 消息提交携带 `version_no`；409 不自动覆盖服务器内容，重新加载后由用户再次发送。
4. 退出登录清除移动端 Cookie 和内存态，不自动删除服务端历史。
5. 对话仍不得发送到未经批准的第三方云端；服务端日志访问、保留和清理沿用 CityBond 运维策略。

## 8. 页面实现模板

每个正式业务功能至少包含：

- 权限检查后的入口和可解释的无权限状态。
- 加载、内容、空数据、筛选无结果、可重试错误和不可重试错误。
- 服务端分页/筛选/排序及明确的查询条件、金额单位和统计日期。
- 完整详情、关联对象、附件、历史和后端实际支持的业务动作。
- 编辑草稿、服务端校验错误定位、提交中防重复、成功回执和版本冲突处理。
- 对下载、打印、上传和长任务的进度、取消及失败恢复说明。

列表卡片只用于摘要，不能代替完整详情；客户端预校验用于即时反馈，最终规则以后端响应为准。

## 10. 验证要求

- 合同层使用固定响应样本和 MockWebServer 覆盖成功及 401/403/409/422/5xx。
- UI 测试覆盖入口权限、加载/空/错误、深层路由、旋转/进程恢复和提交防重。
- 财务测试对照同一后端输入输出，不在 Kotlin 中维护未经服务端确认的公式副本。
- 路由变更运行设备测试；UI/资源变更运行 Lint；网络层变更运行单元测试。
- 真机或模拟器验证必须记录设备、API 等级、后端提交、账号权限、操作路径和结果。
